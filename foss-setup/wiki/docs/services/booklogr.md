## About

BookLogr is a self-hosted personal reading tracker / library (a Goodreads-style shelf: Reading / Already Read / To Be Read / Did Not Finish, with ratings, progress, notes and an optional public profile) running on the Mac mini Docker stack at `/opt/stacks/booklogr`, pinned to `mozzo/booklogr:v1.11.1`. It is a TWO-container app by design and therefore has TWO Caddy vhosts: the React SPA (`mozzo/booklogr-web`, nginx on container `:80`) is served at https://booklogr.tabaska.us, and the Flask API (`mozzo/booklogr`, gunicorn on container `:5000`) is served at https://booklogr-api.tabaska.us. The split matters because the SPA runs in the browser and calls the API cross-origin, so the API must have its own externally-reachable URL — the web container is told where via `BL_API_ENDPOINT=https://booklogr-api.tabaska.us/` (injected into the JS bundle at container start), and the API answers with `flask_cors` allow-all-origins so those cross-subdomain calls succeed. Both containers sit on the shared external `edge` network for Caddy and publish NO host ports. Storage is SQLite at the gitignored `./data/books.db` bind mount (mounted `/app/instance`); the API runs its Alembic migrations on boot. Auth is multi-user (`SINGLE_USER_MODE=False`); `AUTH_ALLOW_REGISTRATION` gates the `/v1/register` route and is opened only long enough to create the household accounts, then flipped to `False` and redeployed. The only secret is `AUTH_SECRET_KEY` (Flask session / JWT signing), sourced from the vault (`booklogr.auth_secret_key`) into `.env` (gitignored; template in `.env.example`), never committed. The unauthenticated API root `GET /` returns `{"name":"booklogr-api","version":"..."}` and is what the `booklogr-serves-consumer` verification check probes end-to-end.

## Troubleshooting

- **The web UI loads but every action fails / login and search do nothing (network errors in the browser console to booklogr-api.tabaska.us).** — The SPA calls the API from the browser, so `BL_API_ENDPOINT` in the booklogr-web container must be the EXTERNAL API URL (https://booklogr-api.tabaska.us/), not an internal container name. Confirm it was injected: `curl -s https://booklogr.tabaska.us/assets/index-*.js | grep booklogr-api`. Also confirm the API vhost is up (`curl https://booklogr-api.tabaska.us/` should return the version JSON). If you changed BL_API_ENDPOINT, `cd /opt/stacks/booklogr && docker compose up -d` to recreate the web container (the value is baked in at start).
- **New users can't sign up — the register page returns an error.** — Registration is deliberately closed after the initial household accounts exist. `AUTH_ALLOW_REGISTRATION` in `/opt/stacks/booklogr/.env` gates the `/v1/register` route via a `@disable_route` decorator. To re-open it, set `AUTH_ALLOW_REGISTRATION=True` and `cd /opt/stacks/booklogr && docker compose up -d`, create the account, then set it back to `False` and redeploy.
- **API paths under /api/... return 404.** — There is no `/api` prefix. The API is served at the vhost root — endpoints are `/v1/books`, `/v1/books/search`, `/v1/register`, `/v1/login`, etc. The unauthenticated health endpoint is `GET /` (returns the name/version JSON).
