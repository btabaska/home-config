## About

Offline maps (lai-17, local-ai buildout) — a fully self-hosted, internet-free US map at https://maps.tabaska.us. The stack (`/opt/stacks/maps` on `mini`) runs two digest-pinned containers on the shared `edge` network: `pmtiles` (`ghcr.io/protomaps/go-pmtiles` in `serve` mode, host `:8899` -> container `:8080`) which serves standard `{z}/{x}/{y}.mvt` vector tiles + a TileJSON out of `data/us.pmtiles`, and `photon` (`rtuszik/photon-docker`, `REGION=usa`, `:2322`) an offline geocoder. `data/us.pmtiles` (~18GB) is a CONUS bbox (`-125,24.5,-66.5,49.5`, zoom 0-15) cut from the ~137GB remote Protomaps daily planet build using `pmtiles extract` over HTTP range requests (NO full-planet download; rebuild with `run-extract.sh`). The fleet's Caddy is a custom build WITHOUT the pmtiles module, so a dedicated go-pmtiles `serve` container is used rather than rebuilding Caddy; `--public-url` makes its TileJSON emit correct public tile URLs. The Caddy vhost `maps.tabaska.us` routes `/pmtiles/*` -> the pmtiles container, `/geocode/*` -> Photon, and everything else to a static MapLibre viewer (`index.html` + generated Protomaps `light` `style.json` + Noto Sans glyph PBFs + v4 sprites + a pinned `maplibre-gl` bundle, all vendored locally under the caddy site dir via `fetch-maps-assets.sh` — nothing loads from a CDN at runtime). The `style.json` is generated by `gen-style.js` against `@protomaps/basemaps@5.7.2` (schema v4, matching the current planet build). Photon downloads a ~10GB US index on first boot and imports it to ~17GB; its API binds `:2322` only AFTER the import finishes, so it is normal for the geocode search box to return nothing for the first hour or so. This is the OFFLINE geocoder; the separate OpenStreetMap MCP wired into opencode uses PUBLIC OSM Nominatim/Overpass (Photon's API is not Nominatim-compatible, so the two are complementary, not layered). LAN/tailnet posture — host ports are published but nothing is forwarded outward. Consumer checks: `maps-pmtiles-serve` (TileJSON + a real US tile) and `maps-photon-geocode` (build-mode aware).

## Troubleshooting

- **The viewer loads but the map is blank / tiles 404, or the maps-pmtiles-serve check fails.** — Confirm the extract landed and the container is serving: `ssh mini 'ls -lh /opt/stacks/maps/data/us.pmtiles; curl -s localhost:8899/us.json | head -c 200'`. If `us.pmtiles` is missing or a `.tmp` remains, the extract did not finish — re-run `ssh mini /opt/stacks/maps/run-extract.sh` (logs in `/opt/stacks/maps/logs/extract.log`). If the file is present but Caddy 404s, check the maps vhost routes in the Caddyfile (`/pmtiles/*` -> `pmtiles:8080`) and reload Caddy.
- **The geocode search box returns nothing / maps-photon-geocode reports mode=building for a long time.** — Photon is still downloading+importing its ~10GB US index (first boot only). Watch progress: `ssh mini 'docker logs --tail 20 photon'`. The Java API binds :2322 only after the import completes; the check reports mode=building (a PASS) until then. If it never completes or the container crash-loops, check disk (`df -h /`) and re-create with `ssh mini 'cd /opt/stacks/maps && docker compose up -d photon'` (the `photon_data` volume persists a completed index).
- **Labels or icons are missing in the viewer, or the browser console shows 404s for /fonts or /sprites.** — The vendored glyph/sprite assets under the caddy site `maps/` dir are missing (they are gitignored and re-fetchable). Re-run `ssh mini /opt/stacks/maps/fetch-maps-assets.sh` to repopulate fonts + sprites + the maplibre bundle, then hard-refresh. If a specific script's labels are blank, its Unicode range is simply outside the fetched Latin/punctuation ranges — extend `RANGES` in the fetch script.
